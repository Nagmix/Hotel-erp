# 15 — تحليل تجربة المستخدم (UX Analysis) — وحدة FXD

> **واجهة محاسبية كلاسيكية صافية**: "Double–click ... to view the following screen" في كل الوظائف الـ19 بلا استثناء · جداول Field/Action/Points-to-Note · F1/F3 · **8 حقول آلية** تجعل المستخدم "مُشغِّل تحقق" لا "مدخل بيانات" · عمق شاشة Master (35 حقلاً + شبكتا popup + قسم عرض تاريخي) يعادل أعلى كثافات المشروع.

---

## 1. أنماط التفاعل المهيمنة

| النمط | الموثق | التكرار |
|---|---|---|
| **Double-click من القائمة** | صيغة الافتتاح الموحدة لكل وظيفة | 19/19 (100% — أعلى اتساق في المشروع) |
| **جدول ثلاثي** | Field / Action / Points to Note | كل الشاشات الموصوفة |
| **F1** | المواقع/المكونات/الفرعية/العملة/UMO/المورد/كود الأصل | ~8 شاشات |
| **F3** (فترة مالية) | Method · FI Posting · الاستعلامات/التقارير | ~7 شاشات |
| **آلي-آلي-آلي** | TotalValue/Rate/Exchange/Local/AssetValue/GainLoss/AssetCode/LastDateDepn | 8 حقول |
| **Double-click على شبكة → popup** | Tax Selection · Component Selection | 2 |
| **Load→Save** | FI Posting | 1 (زر Load قبل Save إلزامياً) |

## 2. إشارات بصرية موثقة

| الإشارة | السياق | القراءة |
|---|---|---|
| **Blue highlight** | FI Posting — subgroups غير مربوطة | "لن يُرحَّل هؤلاء" — إشارة استثناء ساكنة |
| **Waiter Icon? لا — غريب**: هنا **Printer icon غير موجود** | الإشارات الأيقونية غائبة تماماً (بعكس Touch Screen) | وحدة إدوية بلا أيقونات |
| **حقل معطَّل ديناميكياً** | P&L ledger عند تساوي البيع | التغذية الراجعة المحاسبية الفورية |
| **Display-only fields** | Last date depn · Current closing · Installation Date (Transaction) · User/LastUpdated | الفصل الصارم إدخال/ذاكرة |

## 3. تقييم الـ affordances

| الجانب | التقييم | الشاهد |
|---|---|---|
| **تقليل العبء المعرفي بالآلية** | ممتاز | 8 حقول آلية + كود آلي = المستخدم يتحقق لا يحسب |
| **التنبؤ بالأثر المحاسبي** | جيد | Gain/Loss معروض قبل الحفظ + NBV |
| **الوقاية من الخطأ** | متوسط | Load قبل Save في أهم شاشة ✓ لكن بلا Confirm رسالة ✗ |
| **استعادة الأخطاء** | **ضعيف** | لا تعديل (Start Date/MainGroup) · لا Cancel للمعاملات · Rollback للحساب فقط |
| **الشفافية العكسية** | ضعيف | من أزرق تعرف أنه لن يُرحَّل — لكن لا تقرير "ماذا لم يُرحَّل تاريخياً" |
| **الإرشاد** | جيد نقدياً | شرح مفاهيم الإهلاك (فقرات تربوية!) + أمثلة رقمية كاملة — دليل تدريبي نادر |

## 4. أحمال الإدخال (Task Loads)

| المهمة | الحقول اليدوية | المدة التقديرية | الحمل |
|---|---|---|---|
| إنشاء أصل كامل | ~20 + شبكتان | 3-5 د | عالٍ |
| إضافة مكوّن | 6 | <1 د | خفيف |
| بيع أصل | 8 | 1-2 د | متوسط |
| الترحيل الشهري | 4 + Load + Save | <1 د | **خفيف جداً** (أفضل دورة شهرية في المشروع!) |
| تعريف نِسب FY | 4-5 | 1 د | خفيف |

## 5. مآخذ UX (قرارات إعادة البناء)

> **D-FX-4 (UX):**
> 1. شاشة FI Posting: إظهار **عدد القيود والحصيلة قبل Save** (الأصل يعرض الشبكة فقط) + سجل ترحيلات مرئي.
> 2. الأزرق يتحول **تقرير Rejected-for-posting** دوري (سد الشفافية العكسية).
> 3. معاينة القيد ثلاثي السطور عند البيع قبل الحفظ (Debit/Credit مطبوعة).
> 4. تعطيل P&L عند التساوي: يُستبدل برسالة "صافي صفر — سطران فقط" لأن التعطيل الصامت يربك (E-FX-02 يبقى محفوظاً كقاعدة).
> 5. Master بطول 35 حقلاً → تابات (هوية/قيمة/إهلاك/مراجع/شبكات) بدل التمرير الطولي.
