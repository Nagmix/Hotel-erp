# 07 — الصلاحيات والأدوار (Permissions & Roles) — وحدة FXD

> **صفر.** لا ذكر واحد لمستخدم بصلاحية، ولا Authorizer، ولا زر إداري، ولا "User Access" في 25 صفحة — **السابعة في عائلة "بلا صلاحيات"** (CARE/MEM/SLM/TEL/MNT/FNB/FXD)، لكنها الأخطر بينها: هذه وحدة **ترحيل GL مباشرة** (Calculate Rollback + FI Posting + Sales Posting) بلا ضابط وصول واحد موثق.

---

## 1. الدليل على الصفرية

| الفحص | النتيجة |
|---|---|
| كلمات Permission/Privilege/Access/Authorize | ❌ لا مرة (والمفارقة: حقل "Authorized By" موجود في **GTP** المجاورة لا هنا!) |
| Authorizer / Supervisor / Manager | ❌ |
| أثر مستخدم | ✅ **User / Last Updated** فقط في الماسترات (تسجيل سلبي لا صلاحية) |
| POS User Access النمط (وحدة 4) | لا مقابل |

## 2. الأفعال الحرجة بلا ضابط (خريطة الخطر)

| الفعل | الخطورة | الضابط الموثق |
|---|---|---|
| تعريف Start Date (قفل دائم!) | **قصوى** | لا شيء |
| FI Depr Posting → قيود في FAS | **قصوى** | Load→Save فقط (بلا تأكيد) |
| **Rollback إهلاك محسوب** | **قصوى** (يمحو تاريخاً حسابياً) | "roll back options" بلا مواصفة |
| Fixed Assets Transaction (بيع/استبعاد + ترحيل) | عالية | لا شيء |
| تعديل نِسب Depreciation Method | عالية (يغير كل الحسابات) | لا شيء |
| إدخال Depn. Op. Bal | عالية (رصيد موروث بلا مصدر) | لا شيء |

## 3. التوصيف الوظيفي الضمني [INFERENCE]

- **محاسب أصول** يدير الماسترات والحساب الشهري؛ **مراقب مالي** يفترض أن يراجع FI Posting — لكن هذا استنتاج من طبيعة العمل لا من الدليل.
- الفصل الوحيد المرئي: **Calc ≠ Post** (حقلا Last Dep. Calc Date / Last Dep. Post Date) — فصل مرحلي لا فصل أشخاص.

## 4. قرار إعادة البناء

> **D-FX-1:** تُقيَّد كل الأفعال الحرجة الست بأدوار Frappe صريحة (Asset Manager / Accountant / Auditor) + **تأكيد مزدوج لـFI Posting والRollback** مع تسجيل طلب التأكيد في Version Log — سدّ أخطر فجوة صلاحيات في المشروع بوحدة ترحيلية.
