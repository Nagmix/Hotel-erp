# 15 — تحليل تجربة الاستخدام (UX Analysis) — وحدة Front Office

## 1. أنماط استخدام موثقة → دلالات تصميم

| النمط الموثق | الدلالة لواجهتنا | المصدر |
|---|---|---|
| Double-click على الضيف → شاشة الإجراء | تفاعل غير مكشوف — يستبدل بصف/بطاقة + زر إجراء واضح | مواضع متعددة |
| F1 = Help في كل حقل | نمط مساعدة حقلية: يحتاج مكافئ حديث (بحث مدمج/typeahead + مساعدة سياقية) | RES/REG/CAS |
| Right-click → قائمة سياقية (Room Rack) | قائمة سياقية للعمليات على الخلية | RES §3 |
| سحب التواريخ (drag) في Grids | تفاعل سحب للنطاقات (اختيار فترة حجز/بلوك) | RES §2-3 |
| Color coding مكثف | نظام لوني دلالي (يتطلب أسطورة + إمكانية وصول: لا يعتمد اللون وحده) | REG ص15 + RES ص11 |
| مؤشرات شكلية للمؤشر (نقل/امتداد/إطلاق) | معاينة قبل الإجراء (affordance) | RES §3 |
| Tabs (Dirty/All/Occupied) في اختيار الغرف | فلاتر حالة سريعة | REG ص33 |
| F5/F6/F9/F10 اختصارات وظيفية | مخطط اختصارات + قابلية اكتشاف | REG ص20-23 |
| Information Tips (hover) | Tooltips غنية | RES §3 |
| Scan + قوائم (For Guests/Rsvn/City) | تقسيم سياقي واضح للبوابات | CAS §1 |

## 2. مواطن الإحكام الوظيفي (لا يجب فقدانها)

1. **البحث الشامل للضيف** في كل مكان بمعايير متعددة (نمط Scan Booking الموحد).
2. **العرض الفوري للحالة** (Occupied/Dirty/OOO + Current Status/Hotel Position).
3. **تفويض داخل التدفق** (نافذة تفويض عند العملية الحساسة لا قائمة منفصلة).
4. **إثبات بصري للنتيجة** (علامة ✓ خضراء لعدد الغرف، الأزرق للتخصيص).
5. **التحذير قبل الالتزام** (Continue/Abort للعمليات الجماعية).
