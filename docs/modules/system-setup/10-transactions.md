# 10 — المعاملات ودورات الحياة (Transactions) — وحدة System Setup

> SYS وحدة إعداد — لكن لها **دورات حياة إدارية** حقيقية: المستخدم، كلمة المرور، سعر الصرف (زمني!)، الرسالة الفاتورية، وفعالية Applicable From.

---

## 1. دورة حياة المستخدم (الحالة المركزية)

```
[الإنشاء]
Service Provider ينشئ مسؤول النظام (تفويض مطلق) ──┐
   └── System Administrator ينشئ المستخدمين        │
        User + Designation ──> توليد آلي للـ Password
        Password Expires (أيام) + Status=Active     │
                                                    │
[التشغيل]                                           │
   Login (User + Password)                          │
   - تعديل بيانات المستخدم ──> إعادة تعريف الصلاحيات (prompt)
   - انتهاء كلمة المرور (Expires) ──> [دورة كلمة المرور]
                                                    │
[التعطيل]                                           ▼
   Status → Passive ──> لا Login ──> تبويب Inactive User
                                                    │
[إعادة التنشيط]                                     │
   Active checkbox + Reset Password ──> Active ─────┘
```

**ملاحظات:** لا "حذف" موثق للمستخدم (تعطيل فقط!) — [UNCERTAIN] وجود حذف مادي. كل عملية إدارة من User Management تُرى في جدول واحد (ID/Group/Status/Expiry/Last-Changed).

## 2. دورة كلمة المرور

| المرحلة | الحدث | المصدر |
|---|---|---|
| 1 | توليد آلي عند تعيين Designation | ص10 |
| 2 | صلاحية N يوم (≤999) | ص10 |
| 3 | عند الانتهاء | [NOT DOCUMENTED] سلوك الشاشة عند انتهاء الصلاحية (إلزام تغيير؟ حظر؟) — **UNK-023 جديد** |
| 4 | Reset من المشرف → نص جديد **معروض مكشوفاً** | ص38-39 |

## 3. دورة سعر الصرف (Exchange Entry) — كيان زمني حقيقي!

```
New Entry ──> Serial #1 (آلي) + Time + Rate ──> Applicable From
   └─ يمكن حتى 4 إدخالات لكل عملة (Serial 1-4 تصاعدياً)
        └─ الأحدث زمنياً (From/Time) هو الساري
             └─ تعديل: الحالة فقط (تجزئة زمنية لا تعديل أسعار!)
```

- **قيد 4 إدخالات** (ص70) — [UNCERTAIN] ماذا يحدث عند محاولة الخامس؟ (استبدال الأقدم؟ رفض؟).
- الارتباط الموثق: AR يثبّت "exchange rate of the bill date... at the time of settlement" (ACR-OPR) — أي أن سجل Exchange الصحيح زمنياً **أصل مالي لا يمكن تعديله** — البر BR-SYS-11 يحميه.

## 4. دورة الرسالة الفاتورية (Print Bill Message)

```
New ──> From (اليوم) + To + Subject + Outlets + Message ──> Active
   └─ فترة صلاحية تلقائية الزوال بعد To [INFERENCE — لا آلية إيقاف موثقة]
        └─ التعديل مسموح (شاشة Modify موجودة Fig61)
```

## 5. دورة الضرائب (بنية معلنة زمنياً)

```
Tax Code ──> Slabs ──> Structure ── كلها Applicable From ──> تاريخ سريان مستقبلي
   └─ تعديل الحالة فقط للثلاثة ──> **تغيير الضريبة = إنشاء كود جديد بتاريخ جديد**
        └─ السجلات القديمة تبقى للفترات التاريخية (حماية القيود المرحلة)
```

## 6. فعالية Applicable From (آلية عامة)

- الإدخال: **> اليوم فقط** — لا مفاعيل رجعية.
- النتيجة المعمارية: كل مرجعيات SYS **سلاسل إصدارية** — تُفعَّل مستقبلاً ولا تُعدَّل تاريخياً.
- يقابلها في FO: Rate masters بتواريخ — نفس الفلسفة عبر النظام.

## 8. مستندات SYS (تسلسل الترقيم)

لا يوجد ترقيم مستندات في SYS (لا vouchers) — **المعرفات الوحيدة: Code/Serial**:
- Exchange Serial # (آلي تصاعدي من 1).
- Tax Slab Serial (آلي من 0 للشرائح) وTax # (آلي من 1 لبنود البنية).
- Guest Comment Code (آلي؛ 1-25 نظامية).
- أرقام System-Generated: Property/Dept/CC كلها أكواد مستخدم.
