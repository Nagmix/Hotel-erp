# 11 — الأثر المحاسبي (Accounting Impact) — وحدة Care

> **الوحدة الوحيدة في المشروع (حتى الآن) بصفر معاملات مالية موثقة.** الأثر المالي الوحيد المذكور: حقل **Approximate Cost** الوصفي عند إغلاق المهمة + علم **Charges applicable** في تعريفها — وكلاهما بلا أي مسار ترحيل.

---

## 1. المواضع المالية الموثقة (نصياً)

| الموضع | النص الحرفي | المصدر |
|---|---|---|
| تعريف المهمة | "Enter whether if **Charges applicable** for the Task (Yes/No)" | SET ص26 |
| إغلاق المشرف | "In the **Approximate Cost**, if field, enter **value of charges incurred** if any" | OPR ص72 |
| **الكل** | لا شيء آخر — لا فوليو، لا ترحيل، لا أقلام إيراد، لا كودات GL، لا currency | (غياب كامل) |

## 2. التحليل: لماذا هذا "أثر محاسبي صفري"؟

1. **تصميم نمطي لمنتج GSO**: أدوات خدمة الضيوف (IDS Fortune Care) تاريخياً تركز على SLA والإنتاجية، وتترك الفوترة للفوليو (PMS/FO) — لكن الدليل **لا يوثق حتى الجسر** (لا "post to folio" ولا "charge code" ولا "interface to FO folio").
2. **Charges Y/N بلا أثر موثق**: العلم يُجمع في التعريف لكن أين يُستخدم؟ لا شاشة تقرأه موثقاً — **استنتاج فقط**: قد يظهر للتقارير أو للـ IVR — غير معروف (GAP-CA-D01).
3. **Approximate Cost = "تقريبي"**: التسمية نفسها تنفي الدقة المحاسبية — سجل إداري لقيمة الأعباء، مرشح طبيعي لأن يُرحّل لاحقاً في إعادة البناء.

## 3. الحلقة المفقودة المفترضة (رسم تحليلي — غير موثق!)

```
Task Definition: Charges=Y
 → المهمة تُنفذ وتُغلق بـ Approximate Cost = X
 → ═══ فجوة موثقة: لا مسار ═══
 → [المرشح المنطقي] FO Guest Folio (Post Charge) → AR → FAS
   (نفس نمط POS/BNQ: وحدة تشغيلية → فوليو → دورة الإيراد)
```

> هذا الرسم **استنتاج تحليلي** لما يجب أن يوجد في إعادة البناء (قرار F-CA-5)، وليس توثيقاً للمنتج الأصلي — الفرق جوهري ويجب الحفاظ عليه عند الاستشهاد.

## 4. مواضع الأثر غير المالي

| الأثر | التفصيل |
|---|---|
| إنتاجية قابلة للتقييم | Response Time/Staff Productivity Reports — مدخلات HR تقييم محتملة لكن **بلا جسر موثق إلى HRP** |
| إخلال SLA قابل للقياس | Escalation levels/Top Tasks ratio — مؤشرات إدارية بلا ترجمة مالية (لا غرامات/تعويضات موثقة) |
| تكلفة اتصالات | SMS بلا تسعير/محاسبة موثقة (GAP-CA-D05) |

## 5. قرار إعادة البناء (F-CA-5 — يُفصّل في 16)

- **الخيار A (موصى به)**: Task Template بـ "Billable" + Charge Item → عند الإغلاق بتكلفة > 0: إنشاء **Sales Invoice/Folio charge** عبر FO — يبقي الأثر الوصفي التاريخي (Approximate) ويضيف مسار فوترة حقيقي اختيارياً.
- **الخيار B**: إبقاء Care صفرية المال مطابقة للأصل (فقط الحقل الوصفي) — أبسط وأصدق للأصل.
- المعيار: ما لم يقرر العميل الفوترة من المهام، يظل الحقل الوصفي وحده (B) — القرار النهائي في Phase 6.
